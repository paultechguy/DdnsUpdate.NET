# DdnsUpdate 0.2.0

## What's new

DdnsUpdate now runs on .NET 10 (LTS), ahead of .NET 8's end of support in November 2026,
and fixes the bugs that made scheduled runs slow and service failures silent. It also accepts
Cloudflare **API tokens**, which can be limited to editing DNS in the zones you choose,
instead of requiring the Global API Key that can do anything to your account. If you run
DdnsUpdate from Task Scheduler, this release is the difference between a task that finishes
in a second and one that sits for an hour.

### Added

- **Cloudflare API tokens.** Set `apiToken` on a domain or on `defaultDomain` and it is sent
  as `Authorization: Bearer`. A domain's own credentials take priority over the defaults, and
  at each level a token takes priority over a Global API Key.
- **Automatic retries** with backoff when the Cloudflare API has a transient failure.
- **Implicit TLS for email** on port 465, alongside STARTTLS on 587.
- **Startup validation** of the IP address provider list, with a clear message instead of a
  confusing failure later.
- **Clear configuration errors.** Each domain is checked before it is updated, and every
  missing value is reported in one `Invalid configuration` log line.

### Changed

- Runs on .NET 10. The download is still a single self-contained `DdnsUpdate.exe`; nothing
  needs installing on the server.
- **Exit codes mean something.** 0 after a normal run, 1 on failure. It was always 1, so Task
  Scheduler now shows a successful run as `0x0`, and a Windows Service that fails exits so
  its recovery options can restart it.
- **Settings apply without a restart**, including the SMTP server, on the next update pass.
- Email is sent with MailKit instead of the deprecated `System.Net.Mail.SmtpClient`.
- An unreachable IP address provider is abandoned after 15 seconds instead of 100.
- The log file records exception details when something goes wrong.

### Fixed

- In Task Scheduler mode (`maximumDdnsUpdateIterations`), the app waited a full pause
  interval — 60 minutes by default — before exiting after its last pass.
- A missing or zero `afterAllDdnsUpdatePauseMinutes` paused for 60,000 minutes instead of
  one.
- Domain updates were started but not waited for, so the process could exit before they
  finished.
- `messageReplyToEmailAddress` was ignored.
- After an unexpected error, the service could keep running with nothing to do instead of
  stopping so Windows could restart it.

### Upgrading

Nothing beyond replacing `DdnsUpdate.exe`. Existing settings files, including
`appsettings.production.user.json` with the Global API Key, work unchanged. Switching to an
API token is optional and recommended; the README shows how.

Two behaviors to know about:

- If your SMTP server has no `smtpUsername`, DdnsUpdate now connects without
  authentication rather than with the Windows account it runs as.
- If you check the exit code, success is now 0.

### Known issues

- Only IPv4 (`A` records) is detected and updated.
- This release is Windows-only. The 0.1.0 Linux build came from a different code line and has
  no 0.2.0 counterpart.
