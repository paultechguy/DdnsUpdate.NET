Dynamic DNS for Cloudflare · on Windows

Your IP moved. Your DNS already knows.

Your IP address changes. Your DNS keeps up.

DdnsUpdate watches the public address your internet provider gives you, and the moment it changes, points your Cloudflare DNS records at the new one. It touches only what moved, leaves every other setting alone, and runs quietly as a Windows service or a scheduled task — so the things you host at home or in the office stay reachable.

01 The problem

The address you gave the world is only on loan.

You run something worth reaching from outside: a home lab, a media server, a VPN back into the office, a camera system, a small web app for the family. You bought a domain, put it on Cloudflare, and pointed a record at your public IP address. It works. You stop thinking about it.

Then your internet provider hands your connection a new address — after a router reboot, a power cut, a maintenance window, or simply because residential and small-business addresses are leased, not owned. Nothing tells you. Your DNS record still points at the old address, which now belongs to someone else or to no one, and everything behind your domain quietly disappears.

> the failure mode is silence: no error on your side, just a name that resolves to the wrong place.

You find out when a VPN won't connect from a hotel, when a family member says the photos are down, or when a monitoring email you forgot you set up arrives at two in the morning. The fix takes a minute — log in, copy the new address, paste it into the record. Remembering to do it, every time, forever, is the part that doesn't scale.

The address changes on the provider's schedule. The fix should happen on yours — automatically.

02 How it works

One small loop, run on a schedule you choose.

DdnsUpdate repeats the same five steps every pass — every 60 minutes by default. Most passes end at step two, because most of the time nothing has changed, and then nothing is sent to Cloudflare at all.

  1. Ask

    Ask a public “what is my IP” service for your address. The list is yours to edit; a slow or failing service is skipped after 15 seconds and the next one is tried.

  2. Compare

    Compare it with the last address DdnsUpdate saw, which it keeps on disk between runs.

    → unchanged? done until next pass

  3. Validate

    Check every enabled domain has what it needs — zone, record, credentials — and name anything missing.

  4. Update

    Send Cloudflare a PATCH with just the record type, name and new address. Transient API errors are retried with backoff.

  5. Wait

    Sleep until the next pass — or exit, when it's running as a scheduled task or with --once.

That last detail in step four matters more than it sounds. A DNS record carries more than an address: whether Cloudflare proxies it, its TTL, its comment. Replacing the whole record would reset what you didn't send — and quietly switch off the proxy on a record you'd carefully put behind it. DdnsUpdate changes the address and nothing else.

> PATCH, not PUT. fields that aren't sent are left exactly as they were.

If you want to hear about it, DdnsUpdate can email you whenever the address changes, with the old and new values, through any SMTP server you already use.

What's in the box

Small enough to forget about. Complete enough to trust.

Everything below is in the single executable. There's no agent to register, no account to create, and no service of ours in the loop.

Service or scheduled task

Install it as a Windows service that runs a loop, or let Task Scheduler start it, run one pass and exit. Same executable, same settings.

Scoped API tokens

Use a Cloudflare API token that can edit DNS in just the zones you choose. The all-powerful Global API Key still works for existing setups.

Many records

Keep any number of records current, across zones and even accounts. Shared values go in one defaultDomain; updates can run in parallel.

Rides out a bad minute

IP services are tried in turn until one answers; Cloudflare timeouts and rate limits are retried with backoff before a pass gives up.

Edit settings live

Settings files are watched. Add a domain or change the interval and it takes effect on the next pass — no restart.

--dry-run

Reads each record from Cloudflare to prove your token and IDs work, then shows exactly what would change — without updating DNS, saving state, or sending email.

--once

Run one real pass and exit, whatever the settings say. Ideal for a first live test, or for a scheduled task.

One file

A single self-contained DdnsUpdate.exe, about 100 MB, with the .NET runtime inside. Nothing else to install.

Logs you can read

Plain-text daily logs in %ProgramData%, kept for 31 days, and the same lines on screen when you run it by hand.

Honest exit codes

0 when a run finishes normally, 1 when it can't start or fails — so Task Scheduler and service recovery know the difference.

Email on change

Optional notice with the old and new address, via your own SMTP server — STARTTLS, or implicit TLS on port 465.

Open source

MIT licensed C# on .NET 10, with unit tests. Read what it does, build it yourself, change it if you need to.

03 Confidence

Something that edits your DNS has to earn it.

A dynamic DNS updater has one job and a lot of trust: it holds credentials to your domain and runs unattended. So it's built to be predictable first and clever never.

  • It asks before it acts.Run with --dry-run first and read exactly what it would change. Then --once for a single real pass you can watch.
  • It changes only the address.A PATCH with type, name and content. Proxy status, TTL and everything else on the record stay as you set them.
  • It checks before it sends.Each record is validated first; a missing zone, record ID or credential is logged by name and that record is skipped.
  • It only talks to who you tell it to.The IP services you list, the Cloudflare API, and your SMTP server if you enable email. No telemetry, no phone-home.
  • Your secrets stay in your file.Keys and tokens live in a *.user.json file on your machine that upgrades never overwrite and the repository never contains.
  • It's tested where it counts.Unit tests cover the update loop, the request Cloudflare receives, credential precedence and provider fallback.

Quick start

From download to set-and-forget in four steps.

The README walks through each step in detail, including building from source and running under Task Scheduler.

  1. Download

    Grab the latest release and extract it to a folder of its own.

    # for example
C:\DdnsUpdate\DdnsUpdate.exe
C:\DdnsUpdate\appsettings.json
C:\DdnsUpdate\appsettings.production.json

  2. Configure

    Create appsettings.production.user.json beside the exe with your record and API token.

    {
  "cloudflareSettings": {
    "domains": [{
      "isEnabled": true,
      "name": "home.example.com",
      "zoneId": "{zoneId}",
      "recordId": "{recordId}",
      "recordType": "A",
      "apiToken": "{apiToken}"
    }]
  }
}

  3. Dry run, then one real pass

    Preview the changes safely, then let it make them once while you watch.

    .\DdnsUpdate.exe --dry-run
.\DdnsUpdate.exe --once

  4. Install and forget

    From an administrator prompt, register it as a service that starts with Windows.

    sc.exe create DdnsUpdate binPath= "C:\DdnsUpdate\DdnsUpdate.exe" start= delayed-auto
sc.exe start DdnsUpdate
04 Who it's for

Who it's for, and what it deliberately isn't.

It's for the home-labber whose services live behind a residential connection. The small office with a VPN endpoint and no static IP in the budget. The developer who hosts a side project on a machine under the desk. Anyone whose domain already lives on Cloudflare and who would rather never log in to update an A record again.

It's also worth being clear about the edges. DdnsUpdate updates Cloudflare, and only Cloudflare. It tracks your public IPv4 address, for A records. It runs on Windows. Those limits are what keep it small enough to read in an afternoon and dull enough to leave running for years — which, for something that edits your DNS unattended, is exactly the point.

Picture the next time your provider shuffles addresses. A router reboots somewhere in the night. Within the hour, a small program notices, asks Cloudflare to change one field on each of your records, writes a few lines to a log file, and goes back to sleep.

In the morning the VPN connects, the photos load, the side project answers. Nobody had to remember anything.

Your address changed. Nobody noticed.
